# Validation Report: Intel Core i9-13900 + Intel UHD Graphics 770

Shortened run at the owner's request (UHD 770 is not a primary target): correctness in full,
performance with 2 interleaved rounds instead of 6, so CPU ratios within ~10% are not conclusive on
this hybrid-core machine.

## Environment

- **CPU**: Intel Core i9-13900 (8P + 16E, 32 threads, AVX2, no AVX-512), 128 GB DDR4-3200
- **GPU**: Intel UHD Graphics 770 (integrated, unified memory, no cooperative matrices), driver 32.0.101.7088
- **OS**: Windows 11 Pro 10.0.26200, High performance power plan
- **.NET**: SDK 11.0.100-rc.2, runtime .NET 10.0.12
- **Trees**: SimdOnnx `f57b58c` + fix `device/13900-uhd770`; SimdPaddleOCR `feature/simdonnx` `f132a31`
  (old: `main` `33ff8a8`); Sdcb.GcdrNet `main` `b84a948` (old: `2b8fdfe`). New side built with
  `-p:UseLocalSimdOnnx=true`.

## Gap found and fixed: Vulkan dense convs on Intel no-coopmat iGPUs

Before the fix the new engine ran dense convs on the shared-staged `conv_tile` / `gemm` here, while
the old OCR engine had a no-coopmat tier (`gemm_nc` on 8-lane subgroups, `conv1x1_dot`, `convk_dot`).
Per-model graph time (`Sdcb.SimdOnnx.Bench`, 960x736 det, 8x48x320 rec):

| Model | Old engine | New before | New after |
| :--- | :---: | :---: | :---: |
| tiny-det | 36.3 ms | 78.4 ms | 39.0 ms |
| small-det | 85.8 ms | 166.7 ms | 87.6 ms |
| medium-det | 437.7 ms | 792.1 ms | 443 ms |
| tiny-rec | 36.1 ms | 33.0 ms | 13.5 ms |
| small-rec | 166.8 ms | 154.6 ms | 65.5 ms |
| medium-rec | 712.2 ms | 715.6 ms | 233.1 ms |

Fix (`VkDevice.NcDirect`, Intel + no coopmat + 8-lane pinnable subgroup; `GCDRNET_VK_NCDIRECT=0`
disables): `pw_dot` for 1x1 convs with cin <= 96 (cin <= 128 within 2^16 outputs), `conv_kdot` for
kxk with K <= 1024, and a ported `gemm_nc` (64x64 tiles, 8-lane pin, unrolled epilogue for
none / relu / hardswish) for larger 1x1 convs, im2col GEMMs and const Gemms. Thresholds from a sweep
on the three det models. It also applies to GcdrNet's `StagedCoopConv` plans (that option only picks
a coopmat build): GcdrNet 1600x1152 Vulkan 965 -> 875 ms (old 931 ms). Other devices keep their routes.

## Probes

- `GCDRNET_VK_VEC4=0` / `SIMDONNX_VK_STAGE_WC=0`: not needed for the conclusion; the Vulkan gap was
  routing (dense convs), found with per-dispatch profiles (`GCDRNET_PROF=1` in the bench, `--vkprof`).
- GcdrNet `--vkprof 1152 1600` (after the fix, staged conv path): gc 297 ms / dr 565 ms vs old 328 / 616 ms;
  slowest shader `conv_k33s1` (218 + 398 ms, same as old), then `uphead_sc`, `gemm_nc_s`, `convpool_k3`.
  Swapping in the old `conv_k33s1` SPIR-V changed nothing.
- `GCDRNET_WINOGRAD=0` does not change Paddle CPU peak memory (516 vs 511 MB).

## Conclusion against the bar

- **Accuracy**: met (Paddle exact lines equal on CPU, +3 / +6 / -3 on Vulkan tiny / small / medium,
  the same pattern as the other devices; GcdrNet tests pass).
- **Speed**: Vulkan met after the fix (0.94-0.97 Paddle, 0.94 GcdrNet). CPU mostly faster; GcdrNet
  t=16 / t=32 at 1600x1152 within noise (+3-4%), not resolved with 2 rounds.
- **Peak memory**: not met on Paddle CPU (+3-11%, known gap, more per-run garbage: thread-static
  depthwise / Winograd scratch on pool threads) and Paddle Vulkan small / medium (+4% / +3%), GcdrNet
  Vulkan 3200x2304 (+7%). Left open (not a primary platform).
